# HoverClick

A native macOS menu-bar utility with global keyboard shortcuts for left-click
and right-click at the current pointer position, plus an optional BTT-style
single-stroke drawing gesture.

## Mouse shortcuts

Defaults:

- **Left-click:** `⌃⌥⌘A`
- **Right-click:** `⌃⌥⌘S`

Change them from **Configure shortcuts…** in the menu-bar popover. The recorder
requires at least one modifier and temporarily unregisters HoverClick's own
shortcuts while the settings window is open.

## Drawing gesture (optional)

Enable **Drawing gesture → Enable right-click drawing** in Settings. Then:

1. Hold the physical **right mouse button**.
2. Draw one continuous, open **C** shape, starting at the upper-right and
   curving around the left side toward the lower-right.
3. Release the right mouse button.

If the stroke is recognized, HoverClick sends a context-click at the end of the
stroke. A short right-click is replayed as a normal context-click at the point
where it began. A longer unrecognized drag is ignored rather than generating an
unexpected click. The drawing option is off by default and its setting persists
across launches.

This first drawing implementation recognizes a C-shaped unistroke. It does
not yet provide BetterTouchTool's full custom-template editor, per-app scopes,
or dedicated three/four/five-finger trackpad drawing triggers. The feature is
mouse-button based in this version, not a multitouch trackpad trace.

The implementation uses an active session-level Core Graphics event tap to
intercept right-button down/drag/up events while drawing mode is enabled. It
marks and passes through synthetic clicks generated by HoverClick so the event
tap cannot recursively intercept its own output. The feature is designed to
use the same Accessibility permission that HoverClick already needs to post
mouse events; it does not create a listen-only keyboard event tap or ask for
Input Monitoring. The native permission behavior still must be confirmed on
the target Mac.

## Requirements

- macOS 14 (Sonoma) or newer
- Full Xcode toolchain recommended. Swift 6.4 with some standalone Command
  Line Tools installations may omit the SwiftUI `SwiftUIMacros` plugin.

## Build and launch on macOS

From the project root:

```bash
./scripts/build-macos-app.sh
open build/HoverClick.app
```

If the script is not executable after extraction, run:

```bash
/bin/bash ./scripts/build-macos-app.sh
```

The script handles the SwiftPM 6.4 build-backend fallback, uses the actual
SwiftPM binary output directory, and avoids empty Bash-array expansion under
macOS Bash 3.2. If SwiftUI's `SwiftUIMacros.StateMacro` plugin is missing, use a
full Xcode installation, for example:

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer /bin/bash ./scripts/build-macos-app.sh
```

## Permissions

- **Accessibility / Device Control and Data Access:** required to post
  synthetic clicks. On recent macOS versions, the privacy pane may be labelled
  **Device Control and Data Access** rather than **Accessibility**.
- **Input Monitoring:** HoverClick does not request it for its Carbon global
  shortcuts. The drawing implementation uses an active event-filter tap rather
  than a listen-only input monitor; the target Mac must verify that its existing
  Accessibility grant is sufficient for that tap.

If the event tap cannot be created, the app reports that in its status message
and leaves drawing mode disabled. The regular keyboard click shortcuts remain
available.

## Tests

The portable core and unit tests run on macOS or Linux:

```bash
swift test
```

The C drawing recognizer is based on the $1 unistroke approach: it resamples a
stroke, normalizes rotation/scale/translation, and compares its points with a
canonical C template. This is not a full copy of BetterTouchTool's recognizer.

## Known limitations

- Only a single C-shaped gesture is recognized in this first version.
- Right-button presses are briefly held while drawing mode is on so HoverClick
  can distinguish a click from a drag. Very unusual apps that depend on
  right-button-down timing may behave differently.
- The app is ad-hoc signed, not Developer ID signed or notarized. This is meant
  for personal local use.
- Some secure system surfaces, games, remote desktops, or apps with unusual
  input handling may ignore synthetic mouse events.
